# The ROG Strix G615LM

The second laptop the same SSD boots ([g533zw.md](g533zw.md#decisions)):
what it is, what tw does on it, and how the settings made on the G533ZW
fare here. From a probe on 2026-11-19, with the installed tw running and a
monitor plugged in. Its settings in tw are its entry in
[src/machines.h](../src/machines.h).

## The machine

| | |
| --- | --- |
| Model | ASUS ROG Strix G16 G615LM (DMI board name `G615LM`, firmware G615LM.340 of 2026-08-10), Intel Core Ultra 9 275HX: 24 cores, one thread each. 32 GB |
| Panel | `eDP-1`, BOE NE160QDM-NZC, 16 inches, 2560x1600. Two modes: 240 Hz (preferred) and 60 Hz. Adaptive sync from 48 to 240 Hz |
| GPUs | Intel Arrow Lake (`8086:7d67`, `card1`, the boot VGA device, driver `i915`) drives the panel and two DisplayPort outputs, `DP-1` and `DP-2`. NVIDIA RTX 5060 Laptop (GB206M, `10de:2d59`, `card0`, 8 GB, open kernel module 620.70.06) drives `HDMI-A-1`, `DP-3` and an `eDP-2` of its own |
| Battery | holds 77 Wh of the 90 it was designed for; charge limit at 100. Power by the round plug (`ADP0`) or USB-C |
| Thunderbolt | two domains (Thunderbolt 4 generation), security level `user`, `iommu_dma_protection` 1 |
| Wi-Fi and Bluetooth | one Intel BE200 chip: Wi-Fi 7 on PCI (`iwlwifi`), Bluetooth on USB (`8087:0036`), which calls itself Bluetooth as a whole device (class `e0/01/01`) |
| Camera | a USB webcam (`2b7e:c711`, "ASUS FHD webcam", `uvcvideo`) |
| Audio | Intel's (`80:1f.3`), driven by `snd_hda_intel`; the NVIDIA GPU's HDMI sound function besides |
| Ethernet | Realtek RTL8111 (`r8169`) |
| Disk | the G533ZW's external Samsung T7. The internal NVMe disk (Micron, 1 TB) holds Windows, encrypted with BitLocker, and is not mounted |
| Sleep | `s2idle`; the firmware offers `deep` as well. Swap is the 8 GB zram device |

The NVIDIA GPU's `eDP-2` is the panel's second wiring: such laptops have
a switch in the firmware (a MUX) that hands the panel to the NVIDIA GPU.
In that mode the panel would be `eDP-2` on `card0`. `tw-session` would then
pick the NVIDIA GPU, by the built-in panel, and keep it on all session. It
has not been tried, and nothing here needs it.

## GPUs and monitors

`tw-session` takes the Intel GPU first, by the built-in panel
(`TW_SESSION_PRINT=1`, with `WLR_DRM_DEVICES` unset: "first GPU=card1, the
built-in panel"). It adds the NVIDIA GPU only when a monitor is plugged
into it as the session starts, as it was on 2026-11-19:
`WLR_DRM_DEVICES=/dev/dri/card1:/dev/dri/card0`.

A monitor on the NVIDIA GPU was seen working here for the first time on
any machine: a Samsung, 2560x1440 at 60 Hz, through a USB-C hub (VIA Labs,
whose billboard device says it carries DisplayPort). It came up as `DP-3`,
right of the panel. wlroots draws every frame with the Intel GPU and copies
it to the NVIDIA one. Which of the two USB-C ports the hub was in is not
known from `/sys`. The ports wired to the Intel GPU (`DP-1`, `DP-2`) have
not been found either: a monitor there would work when plugged in at any
time and would leave the NVIDIA GPU free to switch off.

After the reboot of 2026-11-19 the same monitor, through the same hub,
came up at 1680x1050: the NVIDIA driver offered nothing larger
(`/sys/class/drm/card0-DP-3/modes` began at 1680x1050, though the monitor's
own EDID still prefers 2560x1440). Before that boot it had offered
2560x1440 and 1920x1080 too. tw takes the best mode it is offered, so the
cause is the link through the hub, which most likely came up with less
bandwidth that time. Unplugging and replugging the hub did not bring
2560x1440 back. An HDMI cable straight into the laptop did: the monitor
came up as the NVIDIA GPU's `HDMI-A-1` at 2560x1440, in the same session.
That it was taken without a new login is because tw had opened the NVIDIA
GPU at that login, for the monitor then on `DP-3`. Use HDMI for this
monitor, not the hub.

Two things it does that looked like faults and are not:

- **A new monitor looks dark.** It shows a workspace of its own, empty,
  and tw draws no background, so it is black until a window goes there or
  the pointer moves onto it.
- **The panel stays on beside it.** Only a closed lid takes the panel out
  of use ([design.md](design.md#the-strip), "The lid").

What the monitor on the NVIDIA GPU costs, with the GPU kept on all session:

| | |
| --- | --- |
| The GPU | awake in P8, 3.4 W and 61 MiB of its memory by `nvidia-smi`, 2 MiB of it tw's. Its sound function still sleeps |
| tw's own memory | 37.8 MB `RssAnon`, against 19 MB in the G533ZW's startup figures with the Intel GPU alone; not measured here without the monitor, and this panel is larger. NVIDIA's EGL libraries are 28.6 MB of tw's resident file pages, mostly shared |
| Each frame | drawn by Intel, then copied to NVIDIA |

A monitor plugged into the NVIDIA GPU after login needs a new login
([setup.md](setup.md#the-nvidia-gpu-off-until-a-program-needs-it)). That
is the design, not a fault: opening that GPU only in case one is plugged
in would cost the above all session.

## Which settings tw uses

The SSD carries one installed tw for both laptops, and tw picks each
one's entry in `src/machines.h` by the board name as it starts (`tw -d`
logs `machine G615LM`). Until 2026-11-19 the build picked a file per board
when it was set up instead, and the installed tw, set up on the G533ZW,
ran the G533ZW's settings here too.

| Setting | Here |
| --- | --- |
| Panel | `eDP-1` at scale 1.25 (2048x1280), the owner's choice. `eDP-2`, its name should the firmware's switch give it to the NVIDIA GPU, at 1.25 too |
| Other screens | scale 1, right of the others |
| Sleep | none: `suspend_after_seconds` and `battery_suspend_percent` at 0 until a suspend by hand has been seen to wake ([Sleep](#sleep)) |

## The G533ZW's system settings here

[g533zw.md](g533zw.md) and [system.md](system.md) list what was changed
outside tw. Checked against this machine:

| Setting | Here |
| --- | --- |
| `blacklist xe` | right: `i915` drives this Intel GPU |
| `options nvme io_queue_depth=128` | applies to the internal disk, which is not used |
| `blacklist ov13858` | no such sensor here; the webcam is on USB and works (`uvcvideo`, `/dev/video0` to `3`) |
| `blacklist kvm_intel`, `kvm` | in force |
| The SOF and AVS audio drivers, kept for this machine | not used for its sound: `snd_hda_intel` drives it, and `snd_sof_pci_intel_mtl` is loaded with no user |
| `blacklist btusb` and the sleep rule | work: no driver, no `bluetoothd`, the adapter asleep (`runtime_status` `suspended`, `control` `auto`) after a boot |

## Sleep

Not tried. As long as neither machine file has a suspend time, tw never
sends this laptop to sleep. The owner's decision to leave sleep off was
about the G533ZW, which did not wake. If a suspend by hand (`systemctl
suspend`, then a key) wakes this one, it can be the machine that
[testing.md](testing.md#seen-on-a-real-machine) says the suspend items wait
for.
